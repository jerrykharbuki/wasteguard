WasteGuardAI / Frontend

Code Guide

A file-by-file explanation of the React and Vite application: what each module does, how data moves through the system, and where the current implementation deserves attention.

Prepared 27 September 2026
Scope: frontend/, including source, configuration, public assets, and project documentation.

1. What This Application Is

WasteGuardAI is a React 18 single-page application built with Vite. It supports account creation and login, citizen waste-dumping reports, browser-camera capture, AI frame analysis through a backend API, evidence uploads to Firebase Storage, incident records in Firestore, and authority review through a map and table dashboard.

Browser entry: index.html -> src/main.jsx -> src/App.jsx -> routes/index.jsx + AuthProvider -> public pages (/login, /register) -> protected layout (Navbar + page outlet + Footer) -> Dashboard, Report, or Admin workflows Report data: camera -> AI API -> image upload -> Firestore incident Admin data: Firestore incidents -> map/table -> status and notes update

2. Root Files and Project Metadata

frontend/index.html

Role: Vite's HTML shell. It defines the document language, viewport metadata, theme color, page title, and the #root element where React mounts. It contains no React exports. The available favicon in public/ is not linked here.

frontend/package.json

Role: Declares the project and its commands. npm run dev starts Vite, npm run build creates the production bundle, and npm run preview serves that bundle. Runtime dependencies are Firebase, Leaflet, React, React DOM, and React Router; development dependencies are Vite and the React plugin. There are no test, lint, typecheck, or format scripts.

frontend/package-lock.json

Role: npm lockfile v3. It records the exact dependency tree, versions, integrity hashes, and resolved registry URLs so installs are reproducible. It is generated metadata, not application behavior; it should normally be changed by npm rather than edited manually.

frontend/vite.config.js

Role: Exports Vite configuration with the React plugin and an /api development proxy aimed at the FastAPI backend. It reads process.env.VITE_BACKEND_URL. A possible configuration mismatch remains: Vite config files generally need loadEnv for project .env values to be available reliably.

frontend/README.md

Role: Human setup and architecture documentation. It describes routes, layout, Firebase variables, build commands, and the intended AI/Firebase flow. Its environment-variable guidance does not fully match the current hardcoded Firebase implementation.

frontend/.env.example

Role: Configuration template naming Firebase and backend settings with the expected VITE_ prefix. It documents the intended deployment contract.

frontend/.env

Role: Local configuration file present in the workspace. Its keys are not prefixed as expected and the current Firebase service does not consume them. It should not be committed if it contains environment-specific values.

frontend/public/favicon.svg

Role: Emerald SVG recycling-symbol favicon. Vite serves it as a public asset, but index.html currently does not reference it.

3. Entry Point, Routing, Context, and Pages

src/main.jsx

Imports the global stylesheet and mounts <App /> into the root element inside React StrictMode. Strict Mode helps expose unsafe side effects during development.

src/App.jsx

Default-exports the top-level App component. Its job is intentionally small: render AppRoutes.

src/routes/index.jsx

Builds the React Router tree. Public routes are /login and /register; authenticated routes are /dashboard and /report; authority-only routes are under /admin. Unknown URLs redirect to /dashboard. The router is wrapped by AuthProvider.

src/context/AuthContext.jsx

Defines the React context and exports AuthProvider and useAuth. It makes user, the Firestore profile, and loading available to the component tree.

src/pages/AppLayout.jsx

Shared authenticated layout. It renders the Navbar, the route's nested Outlet, and the Footer.

src/pages/LoginPage.jsx

Page wrapper that redirects already-authenticated users and otherwise renders Login. It currently redirects an existing authority to /dashboard, while the login form itself routes authorities to /admin; that is inconsistent behavior.

src/pages/RegisterPage.jsx

Redirects authenticated users to the dashboard and renders Register for signed-out users.

src/pages/DashboardPage.jsx

Thin page wrapper exporting the dashboard component.

src/pages/ReportPage.jsx

Coordinates the report workflow. It starts and stops the camera, begins and ends an AI session, captures frames repeatedly, sends base64 JPEGs for analysis, tracks detection state, uploads evidence, and passes final report state to ReportForm. Cleanup and dependency stability need attention: camera object identity can restart the effect, timers are not explicitly tracked, backend sessions may outlive unmount, and captured object URLs are not revoked.

src/pages/AdminDashboardPage.jsx

Loads all incidents, switches between overview/map/table and selected incident details, and applies status or notes updates to local state after review.

4. Hooks and Services

src/hooks/useAuth.js

Subscribes to Firebase Auth state and loads users/{uid} from Firestore. It returns { user, profile, loading }. Error handling is limited, so authentication or profile failures are not represented as a dedicated UI state.

src/hooks/useCamera.js

Owns camera state and exposes start, stop, and captureFrame. getUserMedia supplies a stream; a canvas converts the current video frame into a JPEG blob and object URL. Callers should revoke those URLs after use.

src/services/firebase.js

Initializes Firebase and exports auth, db, storage, analytics, and the app. Configuration is hardcoded even though the README and environment template describe environment-driven configuration.

src/services/authService.js

Exports registration, login, logout, auth observation, and profile lookup. Registration creates Firebase credentials, updates the display name, and writes a default user role profile in Firestore.

src/services/firestoreService.js

Exports incident creation, list, single-record lookup, and updates; it re-exports profile lookup as getProfile. It uses Firestore timestamps and can filter by reporter. Combining a reporter filter with descending creation ordering may require a composite Firestore index.

src/services/storageService.js

Exports uploadEvidence. It stores a Blob, File, or byte array under evidence/{userId}/{fileName} and returns a Firebase download URL.

src/services/aiService.js

Exports session start/stop, frame analysis, and evidence capture helpers. Requests use VITE_BACKEND_URL when present and otherwise /api. captureEvidence is currently unused.

5. Authentication Components

src/components/auth/Login.jsx

Renders the login form, calls Firebase login, retrieves the user's profile, and sends authorities to /admin; other users go to /dashboard.

src/components/auth/Register.jsx

Renders registration fields, validates required values and minimum password length, calls registerUser, then navigates after success.

src/components/auth/ProtectedRoute.jsx

Authentication and role guard. It shows loading, redirects signed-out users to login, and sends users without the required role to their permitted home. This is only a client-side guard; Firebase Security Rules and backend authorization must enforce the same boundary.

src/components/common/Button.jsx

Reusable button with primary, ghost, danger, and outline variants.

src/components/common/Loading.jsx

Accessible status-region loading indicator with a configurable label.

src/components/common/Navbar.jsx

Authenticated navigation bar with brand link, current email, logout control, and route links.

src/components/common/Footer.jsx

Informational application footer.

src/components/common/Sidebar.jsx

Configurable NavLink-based sidebar. It has styling support but is not imported by the current layout, so it appears unused.

src/components/dashboard/Dashboard.jsx

Fetches incidents filtered to the current user and renders a welcome area plus recent reports. It logs load failures rather than presenting a dedicated error state.

src/components/dashboard/RecentReports.jsx

Renders a report grid or an empty state.

src/components/dashboard/ReportCard.jsx

Displays an incident thumbnail, title, Firestore date, coordinates, and status badge.

7. Camera and Reporting Components

src/components/camera/CameraView.jsx

Video preview component. It assigns the active MediaStream to video.srcObject.

src/components/camera/CaptureButton.jsx

Button that calls captureFrame and forwards the resulting image to onCapture.

src/components/camera/DetectionStatus.jsx

Maps idle, detecting, and suspect states to visible status UI. Unknown values fall back to idle.

src/components/reporting/ReportForm.jsx

Collects title and report details, validates title/location, shows uploaded evidence URLs, invokes the map location picker, and writes the incident to Firestore.

src/components/reporting/ImagePreview.jsx

Small image thumbnail component for evidence preview.

src/components/reporting/LocationPicker.jsx

Leaflet/OpenStreetMap map that accepts clicks and browser GPS coordinates. It starts around Metro Manila. Its initialization intentionally captures the initial onChange callback and suppresses exhaustive dependency guidance.

8. Authority and Map Components

src/components/admin/AdminDashboard.jsx

Authority overview showing total, pending, verified, and resolved counts plus the incident table. It can fetch incidents independently, although the current page passes them in.

src/components/admin/IncidentTable.jsx

Clickable table of incidents with reporter, coordinates, date, and status.

src/components/admin/IncidentDetails.jsx

Authority review form showing evidence and AI JSON, then updating status and notes in Firestore. The badge reads incident.status, so it can remain visually stale while a new unsaved status is selected.

src/components/admin/StatusBadge.jsx

Maps pending, verified, and resolved to labels and style classes.

src/components/map/IncidentMap.jsx

Creates Leaflet markers and popups for incidents with valid coordinates. Marker assets come from unpkg. Popup HTML is assembled directly from incident title and status, so unescaped attacker-controlled values could create an XSS vulnerability.

9. Styling

src/index.css

Global stylesheet for the emerald visual theme and all major surfaces: buttons, panels, auth forms, dashboard cards, camera UI, maps, tables, badges, loading animation, and responsive layouts. It also includes selectors for the unused sidebar. It is imported once by main.jsx, so the classes are globally available.

10. Current Risks and Suggested Priorities

  1. Move Firebase configuration to validated environment variables and align .env.example, .env, README, and the implementation.
  2. Escape popup content or use Leaflet DOM APIs in IncidentMap.jsx.
  3. Make camera detection effect dependencies stable, retain timer IDs, stop backend sessions on cleanup, and revoke object URLs.
  4. Enforce authority permissions in Firebase Security Rules and the backend, not just in React.
  5. Add visible error states for dashboard and admin data loads.
  6. Resolve the authority redirect inconsistency between LoginPage and Login.
  7. Add tests and lint/type checks; the current project has none.

11. How to Run and Verify

CommandPurpose
npm installInstall the lockfile-pinned dependency tree.
npm run devStart the Vite development server for interactive checks.
npm run buildCompile the production bundle and catch build-time errors.
npm run previewServe the production bundle locally.

There is no automated test or lint command in the current project. A full runtime check also needs Firebase configuration, browser camera permission, a working backend API, and valid Firestore/Storage rules.
